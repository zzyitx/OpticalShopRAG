# 眼镜店经营台与统一权限中心设计

## 目标

1. 优化点击“眼镜店经营台”后的完整页面，使页面间距、组件和交互风格与现有 PaiSmart 页面保持一致。
2. 修复 admin 下载 Excel 模板被拒绝的问题。
3. 建立覆盖眼镜店、RAG 和系统管理的统一功能操作级权限体系。
4. 为 admin 提供统一权限中心，用于管理角色、用户例外权限和 RAG 组织标签数据范围。

## 设计原则

- 完全复用现有前端设计体系，包括 `NCard`、`NDataTable`、`NTabs`、现有表单、按钮、弹窗、间距、颜色和暗色模式。
- 后端权限校验是安全边界；前端权限控制用于菜单过滤、按钮显示和友好提示。
- 功能权限决定用户能做什么，组织标签决定用户能访问哪些 RAG 数据。
- `ADMIN` 永久拥有全部功能权限和全部数据范围，不依赖数据库授权记录，且不可被降权。
- 保留当前普通用户已有的 RAG 使用能力，默认不授予眼镜店管理权限。

## 眼镜店经营台

### 页面结构

经营台继续使用现有路由入口，页面调整为：

1. 页面根容器使用与其他业务页面一致的外边距和纵向间距，避免内容紧贴左侧侧边栏。
2. 顶部经营概览使用现有卡片组件展示商品数量、库存预警、今日账单和今日实收。
3. 常用操作与经营概览放在顶部区域，操作是否显示由功能权限决定。
4. 下方使用现有页签组件划分业务区域：
   - 商品档案
   - 库存管理
   - 入库管理
   - 出库管理
   - 销售账单
   - 客户历史
5. 各业务区域继续复用现有表格、表单、上传和按钮组件，不引入独立视觉体系。

### 权限交互

- 有查看权限时展示对应页签和数据。
- 无查看权限时不展示对应页签。
- 新增、编辑、删除、导入、下载模板等按钮按操作权限显示。
- 后端拒绝访问时统一展示明确的无权限提示。

## Excel 模板下载修复

当前模板下载通过 `window.open` 发起，无法携带 JWT `Authorization` 请求头，因此已登录的 admin 也可能收到拒绝响应。

修复方案：

1. 前端新增使用现有请求实例的 Blob 下载方法，由请求拦截器自动携带 JWT。
2. 根据响应头或约定文件名创建临时下载链接。
3. 下载失败时使用现有消息组件显示错误。
4. 后端继续执行身份与功能权限校验。
5. `ADMIN` 在后端权限判定中永久放行。

## 统一权限模型

### 权限层次

系统使用“角色权限 + 用户例外 + 数据范围”模型：

```text
ADMIN 有效权限 = 全部功能权限 + 全部数据范围

普通用户有效权限
= 所属角色权限
+ 用户额外授予权限
- 用户明确拒绝权限

RAG 可访问数据
= 有效功能权限
+ 用户组织标签数据范围
```

明确拒绝权限优先于角色权限和用户额外授予权限。

### 核心实体

- 权限目录：定义稳定的功能权限码、所属系统、模块、操作和说明。
- 角色：可由 admin 创建和维护的业务角色。
- 角色权限：角色包含的功能权限集合。
- 用户角色：用户可关联一个或多个角色。
- 用户权限例外：对指定用户额外授予或明确拒绝功能权限。
- 组织标签范围：沿用现有 RAG 组织标签模型，控制数据可见范围。

### 权限码规则

权限码采用稳定、可读的点分格式：

```text
store.dashboard.view
store.product.view
store.product.create
store.product.update
store.inventory.view
store.inventory.inbound.create
store.inventory.outbound.create
store.sales-bill.view
store.sales-bill.create
store.sales-bill.update
store.sales-bill.import
store.sales-bill.template.download

rag.chat.use
rag.knowledge-base.view
rag.knowledge-base.upload
rag.knowledge-base.manage
rag.model-provider.manage

system.user.view
system.user.manage
system.permission.manage
```

具体权限目录以现有接口和页面操作为基础补齐，避免创建没有实际校验点的权限码。

### 后端鉴权

- 建立统一权限解析服务，根据当前用户计算有效权限。
- `ADMIN` 在权限解析服务中直接返回全权限结果。
- 业务接口使用统一权限校验机制，不在控制器中散落用户名或角色字符串判断。
- RAG 现有组织标签过滤继续负责数据隔离，并在 admin 场景下保留全范围能力。
- 无权限统一返回 HTTP `403` 和稳定错误码。

## 权限中心

### 页面入口

- 新增独立“权限中心”路由与侧边栏入口。
- 仅 `ADMIN` 可查看和访问。
- 页面布局、卡片、表格、搜索、弹窗和操作按钮完全复用现有用户管理页面风格。

### 页面功能

权限中心包含三个页签：

#### 角色管理

- 查看、新建、编辑和停用业务角色。
- 按眼镜店、RAG、系统管理分组配置操作级权限。
- 展示角色关联用户数量。
- 系统保留角色可限制删除，避免迁移后的用户失去基础权限。

#### 用户授权

- 搜索和查看用户。
- 为用户分配一个或多个角色。
- 配置用户额外授予权限。
- 配置用户明确拒绝权限。
- 继续配置现有组织标签和主组织标签。
- 展示用户最终有效权限摘要，便于 admin 排查授权结果。

#### 权限目录

- 展示所有权限码、所属系统、模块、操作和说明。
- 首期权限目录由代码和初始化数据维护，页面只读，避免运行时误改权限码导致鉴权失效。

## 前端权限能力

- 登录用户信息中返回角色、有效权限码和组织标签摘要。
- 认证状态模块提供 `isAdmin` 和统一 `hasPermission(permissionCode)` 能力。
- 菜单根据查看或管理权限过滤。
- 页面和操作按钮使用统一权限判断，不重复实现权限逻辑。
- 前端不得将按钮隐藏当作安全控制，接口始终由后端再次校验。

## 迁移策略

1. 创建保留当前普通用户现有 RAG 使用能力的系统默认角色。
2. 将现有普通用户关联到该默认角色。
3. 默认角色不包含眼镜店管理权限。
4. 保留现有用户组织标签和主组织标签。
5. 现有 `ADMIN` 用户不需要角色授权即可拥有全部权限。
6. 初始化过程必须可重复执行，避免重复创建角色、权限和关联记录。

## 错误处理

- 未登录请求继续返回 `401`。
- 已登录但无功能权限返回 `403` 和稳定错误码。
- 无 RAG 数据范围时返回空数据或明确禁止，沿用对应接口当前语义。
- Excel 下载失败时前端不创建空文件，并显示后端错误信息。
- 权限配置冲突时，页面明确展示“明确拒绝优先”的计算规则。

## 测试与验证

### 后端

- `ADMIN` 对全部受控接口始终允许。
- 普通用户角色权限生效。
- 用户额外授予权限生效。
- 用户明确拒绝权限覆盖角色和额外授予。
- 现有 RAG 组织标签数据隔离保持有效。
- 默认角色迁移可重复执行且不产生重复数据。
- 无权限接口返回 `403`。

### 前端

- 经营台页面拥有与现有页面一致的外边距、卡片、页签、表格和暗色模式表现。
- 菜单、页签和操作按钮根据权限正确显示。
- 权限中心仅 admin 可访问。
- 角色、用户例外和组织标签配置流程可用。
- Excel 模板下载携带 JWT，admin 可成功下载。
- 类型检查和生产构建通过。

## 范围约束

- 本次不重做现有页面视觉体系。
- 本次不移除或替换 RAG 组织标签机制。
- 本次不允许普通管理员调整 `ADMIN` 的永久全权限规则。
- 权限目录首期不提供运行时新增或修改权限码功能。
- 其他业务功能只接入权限校验，不进行无关重构。
