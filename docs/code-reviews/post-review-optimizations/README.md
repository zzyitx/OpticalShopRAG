# 审查后优化报告

本目录用于记录代码审查意见经过项目上下文核验后的处理结果。审查意见是待验证的建议，不是默认实施清单；每次只采纳对当前项目有明确正确性、安全性、可维护性或用户体验收益的事项。

## 文件命名

```text
<主题>-post-review-optimization-YYYY-MM-DD.md
```

同一主题同一天有多轮优化时，在日期后增加 `-02`、`-03` 等序号。

## 必填内容

每份报告必须包含：

1. 原审查报告路径、审查日期和本次处理范围。
2. 每条意见的结论：采纳、部分采纳、不采纳或延期。
3. 判断该意见是否真正有益，以及对应的代码或运行证据。
4. 实际修改的文件和行为变化。
5. 测试、编译、类型检查、格式检查和运行态证据。
6. 项目能否持续启动；环境阻塞必须与代码缺陷分开描述。
7. 冗余评估：是否引入重复逻辑、无使用方抽象或额外工具链。
8. 耦合评估：新增依赖方向、跨层影响和后续维护风险。
9. 未完成验证、已知警告和后续条件。

## 结论规则

- 未运行验证命令，不得写“通过”。
- 只完成编译，不得写“项目已正常启动”。
- 端口短暂监听后应用退出，不得写“持续运行正常”。
- 外部依赖不可达时，应记录依赖地址、端口和应用日志证据，不得通过临时改配置掩盖问题。
- 被代码事实证伪的审查意见应明确不采纳，避免为了响应审查而制造重复实现。
